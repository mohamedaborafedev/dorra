# تقرير صور الملابس وإعادة قياس الأداء

تاريخ التنفيذ: 28 أكتوبر 2026. النتائج محلية وليست ضمانًا لبيئة الإنتاج.

## الصور والتوزيع

تم تنزيل 10 صور ملابس من Unsplash بصيغة JPEG وأبعاد 480×320، بإجمالي 303,653
بايت، نحو 297KiB. تمت مراجعتها بصريًا والتحقق من نوعها وأبعادها. الملفات في
`public/clothing/` وتُخدم محليًا دون طلبات خارجية أثناء تصفح المكتبة.
مصدر كل صورة وبصمتها في [ملف المصادر](../clothing-images.json)،
والترخيص في [Unsplash](https://unsplash.com/license).

تم تغيير thumbnail فقط للـ100 ألف تصميم بتوزيع شبه عشوائي قابل لإعادة الإنتاج:
CRC32(seed + id) modulo 10. كل صورة مستخدمة في 9,817–10,153 تصميمًا.
الأعداد الدقيقة في [ملف التوزيع](../clothing-distribution.json).
لا تغيير للعناوين أو الحالات أو التواريخ. الصور مشتركة وليست 100 ألف نسخة؛ حذف
تصميم أو استبدال صورته لا يحذف الملف المشترك. إخفاء أرقام العناوين التجريبية محفوظ.

المسارات القديمة محفوظة محليًا في:
`storage/app/private/backups/design-thumbnails-20261028-131947-9e54107a.jsonl`.
كل سطر يحتوي id وthumbnail السابق. لم تُحذف ملفات الصور القديمة. أي استرجاع لاحق
يتطلب مراجعة التغييرات الأحدث قبل تطبيق المسارات؛ لم يُنفذ استرجاع تلقائي.

## إعادة قياس MySQL

نفس المنهجية: 3 warmups و20 عينة لكل variant، وترتيب متناوب، ومقارنة IGNORE INDEX
مقابل اختيار optimizer داخل read-only REPEATABLE READ snapshot.
الـ100 ألف سجل متطابقة بين طرفي الجولة الجديدة، والبصمة ثابتة قبل وبعد.
الجولة القديمة محفوظة منفصلة؛ اختلاف بصمتها طبيعي بسبب تغيير thumbnail.

القيم التالية هي وسيط زمن PDO SELECT مع جلب النتائج بالمللي ثانية؛ لا تشمل HTML
أو تحميل الصور. الصور نفسها لا تُخزن في MySQL، بل المسار فقط.

| الاستعلام | indexed سابق | baseline جديد | indexed جديد |
| --- | ---: | ---: | ---: |
| أحدث 24 تصميمًا | 0.991 | 70.058 | 0.727 |
| القسم والحالة | 1.036 | 53.743 | 0.862 |
| البحث مع القسم والحالة | 1.095 | 49.721 | 1.180 |
| COUNT بدون فلتر | 17.095 | 10.748 | 17.229 |
| OFFSET 96000 | 125.223 | 118.249 | 111.059 |

كل SQL وbindings وEXPLAIN وEXPLAIN ANALYZE والعينات وP95 في
[النتائج الجديدة](../performance-clothing-results.json). لم تُضف أو تُحذف فهارس،
ولم يُفرغ cache أو يُعد تشغيل السيرفر. الإحماء وقراءة البصمة يجعلان التجربة warm-cache.
حدود المنهجية في [التقرير الأساسي](../performance.md).

المقارنة التاريخية ليست سببية: تغيرت البيانات ووقت التشغيل وحالة الجهاز وcache؛
لا تُنسب الفروق إلى الصور وحدها. COUNT بلا فلتر ما زال أبطأ بالخطة المفهرسة المختارة،
والصفحات العميقة ما زالت مكلفة. لا يوجد ادعاء بقياس cold cache أو مليون سجل أو حمل متزامن.

## Playwright

أُعيد القياس بعد انتهاء MySQL بحساب Admin، وتشغيلَي إحماء و10 عينات لكل صفحة،
وcache المتصفح الافتراضية مفعلة. وسيط load event هو 411.85ms للقائمة الرئيسية
و434.05ms للفلاتر المجتمعة في الصفحة الثانية. توقيت المتصفح منفصل عن SQL.
العينات في [قياسات المتصفح الجديدة](../playwright-clothing-performance.json).

بعد القياسات، جرى التمرير عبر الجدول والتحقق من تحميل وفك ترميز 24/24 صورة،
بأبعاد 480×320. الصفحة المختبرة استخدمت 8 ملفات مختلفة من الصور العشر.
load event لا ينتظر الصور lazy خارج مجال الرؤية؛ التحقق بالتمرير لم يُنسب له
زمن تحميل كامل مزعوم. [لقطة المكتبة](evidence/clothing-library.png).

نجح 52 اختبارًا و202 assertions، وفحص PHPStan بلا أخطاء. يشمل الاختبار الجديد
حماية الصور المشتركة من الحذف مع التصميم وعرضها وإخفاء لاحقة العنوان.

## إعادة التشغيل

```powershell
# اختياري: يغير المسارات وينشئ نسخة رجوع جديدة
php scripts/assign-clothing-images.php
# قياس دون تغيير البيانات
php scripts/benchmark-database.php --runs=20 --warmup=3 --output=docs/performance-clothing-results.json
```

لقياس المتصفح، شغّل `scripts/benchmark-browser.js` من Playwright MCP بعد الدخول،
منفصلًا عن SQL. احتفظ بالنتائج السابقة للمقارنة التاريخية.
